# P8 plan: reviewer-console polish

**Phase:** plan (stop for approval). **Branch:** `p8-ui-polish`. No pass marker file yet.

## Goal

Nine display fixes on the Streamlit reviewer console. Same pages, same API. Queue rows name the case and open it. Case, review, and audit pages show human sentences instead of raw JSON. Sample-mode spinner text matches the real wait.

## Scope

| Path | Action |
|---|---|
| `ui/screens.py` | Queue label, open-case navigation, outcome-reason bullets, spinner text, eligibility bullets, replay and verify messages |
| `ui/components.py` | Control-table columns, evidence expander, shared humanisation helpers |
| `tests/unit/ui/test_polish.py` | **Create** — acceptance tests, marker `p5a` (existing marker; `pyproject.toml` is out of scope) |
| `tests/unit/ui/conftest.py` | Only if a test needs a richer fake replay / verify / eligibility payload |

**Do not touch:** `app/`, `eval/`, `docs/`, `ui/client.py`, `app/schemas/api.py`, `app/schemas/case.py`, pages under `ui/pages/` (they already call `ui.screens`), fixtures under `tests/fixtures/`.

## Helpers (`ui/components.py`)

Pure functions, no Streamlit, so tests can assert text without a page run:

```python
OUTCOME_REASON_TEXT: dict[str, str]
ELIGIBILITY_REASON_TEXT: dict[str, str]
REPLAY_CHECK_TEXT: dict[str, str]  # policy_hash, record_hash, contract_signatures

def humanise_outcome_reason(code: str) -> str: ...      # dict, else the raw code
def humanise_eligibility_reason(code: str) -> str: ...  # dict, else the raw code
def replay_check_line(key: str, ok: bool) -> str: ...   # "✓ policy hash matches" / "✗ record hash mismatch"
def evidence_summary_line(fact: dict) -> str: ...       # "`{key}` = `{value}` → `{state}`"
def evidence_from_line(fact: dict, provenance: dict) -> str: ...  # "From: …"
def control_rows(controls, facts) -> list[dict[str, str]]: ...    # four columns only
```

`None` values render as `null`. Unknown codes render as the raw code. `replay_check_line` humanises unknown keys by replacing `_` with spaces.

## The nine fixes

### 1. Queue row label — `page_queue`

Today the row is the outcome badge, then `{vendor} · risk {n} · {status}`, then the tier chip. `case_id` is only in the button key.

Add the id on that middle line:

`CASE-0007 · {vendor} · risk {n} · {status}`

Badge and tier chip stay as they are.

### 2. Open case — `page_queue`

Today the button sets `nav_case_id` and stops. The case page reads `query param case_id` or `session_state["nav_case_id"]`.

On click:

```python
st.session_state["last_case_id"] = item.get("case_id")
st.session_state["nav_case_id"] = item.get("case_id")
st.switch_page("pages/case.py")
```

`last_case_id` is what this pass was asked to set (new assessment already sets it). `nav_case_id` stays, because that is the key `page_case` already reads. Setting only `last_case_id` would open Case on the empty state.

### 3. Case header reasons — `page_case`

`record["outcome_reasons"]` becomes a bullet list under the outcome badge. Each bullet is `humanise_outcome_reason(code)`. Under each bullet, `st.caption(code)` shows the raw code.

Approved map:

| Code | Text |
|---|---|
| `CONTRADICTION` | Contradiction on a system-of-record claim |
| `CONTROL_FAILED` | One or more controls failed |
| `EVIDENCE_MISSING` | Evidence is missing for a required control |
| `LOW_CONFIDENCE_ABSTAIN` | Confidence below the gate — abstained |
| `HARD_GATE_DECLINE` | A hard gate requires decline |
| `HARD_GATE_ESCALATE` | A hard gate requires escalation |
| `ALL_REQUIRED_CONTROLS_MET` | All required controls met |
| `UNTRUSTED_CONTENT_TAMPERING` | Untrusted content tampering detected |

Unknown codes (including `CONDITIONS`, `HUMAN_REVIEW`) use the raw code as the bullet and still caption it.

The report `summary` paragraph stays under the bullets. It is the reporter narrative. On the fixture it still contains the raw reason codes inside that sentence.

### 4. Controls table — `control_table`

`rule_id` is the same string as `control_id` (`C01` and `C01`). Drop that column.

Columns, in order:

| Control id | Name | Status | Fact ids |
|---|---|---|---|
| `control_id` | `title` | `state` | comma-joined `fact_ids`, or `—` |

### 5. Evidence expanders — `evidence_chip`

Today the open expander ends with `st.json({"key", "value", "state"})`.

Replace the body with:

1. One line: `` `{key}` = `{value}` → `{state}` `` (`st.markdown`).
2. `From: {sentence}` (`st.write`).
3. Nested expander **See raw**, collapsed, `st.code(json.dumps(...), language="json")` of that same `{key, value, state}` object.

The expander title (system · query · record · field, or provenance kind) stays.

**`evidence_text` is not on the payload.** `Fact` and `Provenance` have no such field, and nothing in the repo writes one. Recommendation, used unless you say otherwise:

1. `fact["evidence_text"]` if present.
2. Else `provenance["quote"]` (the only human sentence on provenance).
3. Else `From: No narrative is stored for this fact.`

The default view is those two lines. Raw JSON is only inside **See raw**.

### 6. Spinner — `page_new_assessment`

One string change inside the existing `st.spinner`. No stage cycling, no timer, no extra status writes.

`Running the assessment loop — this takes 2–5 seconds in sample mode, up to 60 seconds live…`

### 7. Review eligibility — `page_review`

`Check eligibility` today does `st.info(json.dumps(hint))`. The dry-run body is `{eligible, reasons: list[str]}`.

Render `reasons` as bullets via `humanise_eligibility_reason`, with `st.caption` of the raw code under each bullet. Empty `reasons` and `eligible: true` → `st.success("Eligible to create a precedent")`. No `json.dumps` on this path.

Approved map:

| Code | Text |
|---|---|
| `mitigation_not_true` | The mitigation fact is not TRUE — this precedent can't apply |
| `no_exception_control_failing` | No exception-eligible control is failing |
| `non_exception_control_failing` | A control that can't be excepted is failing |
| `reviewer_authority` | The reviewer's role is below the required authority |
| `precedent_age` | The precedent is older than the 365-day window |
| `retrieval_quality` | H-MEM confidence or relevance is below the threshold |
| `tier_risk` | This case's risk tier is higher than the precedent's |

**Live dry-run codes differ.** `check_eligibility` in `app/memory/precedents.py` emits `no_failing_controls`, `non_exception_control_failing`, `no_exception_control_failing`, `decision_not_approving`, `reviewer_role_insufficient`, `mitigation_not_true`. It does not emit `reviewer_authority`, `precedent_age`, `retrieval_quality`, or `tier_risk` (those are policy-engine `failed_criteria`).

Recommendation: keep the approved map exactly, and add three aliases so the codes this button actually receives are not left raw:

| Code | Text |
|---|---|
| `reviewer_role_insufficient` | same sentence as `reviewer_authority` |
| `no_failing_controls` | No required control is failing |
| `decision_not_approving` | The review decision is not an approval |

Say no and unknown codes stay raw, per the fallback rule.

Submit-review `st.success(json.dumps(result))` is unchanged. It is not one of the nine fixes.

### 8. Audit replay — `page_audit`

`client.replay` returns `{match, diff, checks: {policy_hash, record_hash, contract_signatures}}` (bools).

- `match` true → `st.success("Match — the decision replays identically")`
- `match` false → `st.error("Mismatch — see diff")`, then each `diff` entry as a bullet (plain strings, not `st.json`)
- For each key in `checks`: `replay_check_line` → `✓ policy hash matches` or `✗ record hash mismatch`

### 9. Audit verify — `page_audit`

`GET /audit/verify` returns `{ok, first_bad_seq}` only. There is no entry count on that payload, and this pass cannot change the schema.

- `ok` false → `st.error(f"Chain broken at sequence {result['first_bad_seq']}")`
- `ok` true, count known → `st.success(f"Chain intact — {n} entries across all cases")`
- `ok` true, `/health` fails or the count is missing → `st.success("Chain intact")`

**Where `n` comes from.** `result["entries"]` when that key is an int (tests and any future field). Otherwise `client.health()["audit_chain_length"]`. The count is the whole audit log, not the open case, so the success text says "across all cases". A failed health call drops the count rather than inventing one.
