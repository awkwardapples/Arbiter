## Behaviour

`_step_traces` keeps one temp directory and one final validation. A new helper copies `/app/logs` and looks for case traces:

```python
def _wait_for_case_traces(dest: Path) -> tuple[list[Path], list[Path] | None, str | None]:
    """Poll the container logs until a trace-run-* file is present.

    Returns (case_traces, all_trace_files, error). error is a docker cp failure
    or the existing absence message after 20 empty polls.
    """
```

Poll rules:

1. Up to 20 copies, `docker cp arbiter-clean-clone:/app/logs/. <dest>`. Clear `dest` before each copy so a later copy is the only snapshot.
2. A case trace is still `trace-*.jsonl` whose name starts with `trace-run-`. The same prefix the validator already treats as a collaborative run.
3. If that list is non-empty, return it and every `trace-*.jsonl` from that copy. No further sleep.
4. If it is empty, and this is the first empty poll, print `waiting for traces...` once, flushed, so the CI log shows the wait. Later empty polls stay quiet.
5. Sleep 0.5 s between empty polls. Do not sleep after the 20th miss, and do not sleep when the first poll already finds files. Worst case is 19 × 0.5 s (about 9.5 s) plus the copy time.
6. After 20 empty polls, return `no case traces in the container logs`.
7. If `docker cp` fails, return its stderr immediately. That is a different failure from a late flush, and today's message for it stays.

After the helper returns files, the rest of `_step_traces` is unchanged:

- `validate_file` on every `trace-*.jsonl`, with `require_collaboration` only for `trace-run-*` and `require_live=False`.
- Container stdout must contain `Uvicorn running` or `run_id=`.
- Success detail stays `traces ok`. Validation errors stay the first five joined messages.

There is no separate "these six files are the six examples" comparison in step 4 today. Step 3 checks the six example outcomes. Step 4 checks that case traces exist and that `check_trace` accepts them. The poll does not add or remove that validation, and it does not treat a non-empty directory of status traces (`trace-zetaris-status`) as success.

`time` is already imported. No new dependency. The file is 363 lines; the helper keeps it under 400.
