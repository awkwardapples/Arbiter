## Decisions already made

1. **The stray "Cases" is the page link, not a subheader.** `page_evaluation` ends with `st.page_link(..., label="Cases")`. That is what `test_p11_evaluation_split` locks. Remove the link and the `_QUEUE_PAGE` constant. Do not add a "Cases" subheader.
2. **Metric order changes.** The row today is Cases, Most recent, Data backend, LLM provider. The brief wants Cases, Data backend, LLM provider, Most recent. `live_run_summary` stays as it is. Only the column order changes.
3. **Strip the H1 at render time.** `eval/results/.../summary.md` is not edited. Its only heading is the first line, `# Evaluation`. Streamlit turns a markdown `# ` into an `h1`, and AppTest records that as a second `at.title`. `strip_leading_h1` drops a prefix of lines that start with `# ` (a space after the hash, so `##` is left alone) before `st.markdown`. Later headings, if a future summary had them, stay.
4. **Section chrome stays `_section`.** That helper is already `st.subheader` plus `st.caption`. The page title remains the one `st.title("Evaluation")`. No `st.header` and no markdown headings are added inside the sections.
5. **`st.logo` is the path that will run.** Installed Streamlit is 1.66.1. `st.logo(image, *, size="small"|"medium"|"large", ...)` exists. The version check parses numeric components (`(1, 66) >= (1, 31)`), not a string compare, and also requires `hasattr(st, "logo")`. The sidebar-image branch stays in the source for older Streamlit. The report will say 1.66.1 took the `st.logo` branch.
6. **Copy the PNG as bytes.** The source file is `/mnt/d/Downloads/no white Arbiter logo.png`: 800×300, palette (color type 3), with a `tRNS` chunk. `shutil.copyfile` into `docs/img/arbiter_logo.png`. Do not re-encode it. A Pillow save can drop the palette transparency.
7. **Logo call site is `ui/app.py`, before navigation and before the sidebar status.** `st.logo` draws in the sidebar header above the nav on every page. The fallback `st.sidebar.image(..., width=200)` only stays at the top if it is the first sidebar call, so it runs before `_sidebar_status()`. Pages are not edited. `ui/pages/*.py` already delegate to `ui.screens`.
8. **AppTest cannot see the logo proto.** Logo is a forward message, not an element, so there is no `at.logo`. The test locks the file bytes and the call in `ui/app.py`. Existing page smoke already runs `AppTest.from_file("ui/app.py")`, so a missing or broken image fails the whole UI suite. The asset and the `st.logo` call land in the same implementation commit.

    """Drop a leading run of lines that start with '# '. Leave the rest, including later headings."""

def _render_eval_markdown(text: str) -> None:

## Logo

```python
_LOGO = _ROOT.parent / "docs" / "img" / "arbiter_logo.png"

def _streamlit_supports_logo() -> bool:
    # numeric (major, minor) >= (1, 31) and hasattr(st, "logo")

def _install_logo() -> None:
    if _streamlit_supports_logo():
        st.logo(str(_LOGO), size="large")
        return
    st.sidebar.image(str(_LOGO), width=200)
```

`main` calls `_install_logo()` after `st.set_page_config` and before `_sidebar_status()` and `st.navigation`.

Repo root is `_ROOT.parent` because `_ROOT` is `ui/`. The image is not under `ui/docs`.
