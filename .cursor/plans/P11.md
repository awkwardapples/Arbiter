# P11 plan: professional reviewer console

**Phase:** plan. **Branch:** `p11-professional`. Marker stays `p5a`. Verify with `python scripts/tasks.py verify-pass --pass 5a`.

## Goal

Each page reads as a finished TPRM tool: a plain title, one caption, then the work. Tutorial expanders and teaching paragraphs go away. Review checks eligibility as soon as a case is selected, and the precedent fields are multiselects that fill themselves when the case qualifies. Evaluation splits the fixed benchmark from what this instance has actually run.

## Decisions already made

These are the readings of the brief I will build unless you change them.

1. **A review can still be recorded when the case is ineligible.** Rationale, Decision, Submit, and Dry-run stay enabled. Mitigations, Conditions, Other condition, and Create precedent are enabled only when the dry-run says eligible. On submit while ineligible, `create_precedent` is forced false and the mitigation and condition lists are empty. The amber caption says a review can still be recorded; disabling the whole form would contradict that.
2. **Decision stays on the form.** `ReviewRequest.decision` is required, and eligibility depends on an approving decision. It is the first field under the status box. The brief's field list did not name it.
3. **No live-runs route.** `GET /health` and `GET /cases` already carry the count, the latest timestamp, the data backend, and the LLM provider. `app/api/routes_meta.py` is not edited. No schema change.
4. **Audit events do need a route.** Nothing returns chain rows. See the exception below. Case rows will not be labelled as audit events.
5. **Replay outcome lines stay.** `Match — the decision replays identically` and `Mismatch — see diff` stay so the check-line tests keep their anchors. The captions under them become the short analyst sentences.
6. **Verify button label stays** `Verify audit chain`, with `type="primary"`, inside a card at the top of Audit.
7. **Case caption uses the record.** `record.run_id` and `record.created_at`. `CaseDetail` has no separate created field, and this pass does not add one.
8. **Glossary goes.** It is a tutorial expander on every page. No test asserts it.

## Audit route (the one file outside `ui/` and `tests/unit/ui`)

`GET /audit/recent?limit=20` reads `var/audit.db` the same way `_audit_length` does. Missing file returns `[]`. `limit` is clamped to 1..100.

```python
class AuditEvent(BaseModel):
    seq: int
    ts: str
    case_id: str
    event_type: str

@router.get("/audit/recent", response_model=list[AuditEvent])
def audit_recent(limit: int = 20) -> list[AuditEvent]: ...
```

Columns returned: `seq`, `ts`, `case_id`, `event_type`. Payload JSON stays in the database. Read-only. No new dependency.

`ArbiterClient.audit_recent(limit: int = 20) -> list[dict[str, Any]]` calls that path.

No test file under `tests/unit/api/` (P4-B). The page test uses the fake. The SQL is the same shape as the existing length query.

If you reject the route: drop `routes_meta.py`, `ui/client.py`, and `conftest.py`. Audit then shows the verify card, `st.info("Audit events are not on the API.")` when the chain length is unknown, and the replay selector. I will not paint the case queue as events.

## Page structure

Every page starts with `st.title` then `st.caption`. Sections use `st.subheader` plus one caption. Empty → `st.info`. Error → `st.error`. Success → `st.success`. Warning → `st.warning`. Raw JSON → `see_raw` (`See raw`, collapsed, `st.code(..., language="json")`).

### New assessment

Title, caption, the existing vendor / JSON intake, `Run assessment`. No expander. On success, subheader `Result`, the existing success line, and `see_raw` of the response. The run still stores `last_case_id` and `nav_case_id`.

### Cases

Title, caption, one `st.dataframe` of the queue in API order (already sorted by residual risk). Columns: case, vendor, outcome, tier, residual risk, status, created. Outcome and tier filters and the per-row cards go away.

Open: `st.dataframe(..., on_select="rerun", selection_mode="single-row")`. A selected row sets `last_case_id` and `nav_case_id` and calls `st.switch_page("pages/case.py")`. `CASE-0007` remains visible in the frame, which is what the queue test will assert.

### Case

1. Title `{case_id} · {vendor}` from the detail payload. Vendor text is data, not a literal in source.
2. Caption `{run_id} · {created_at}`.
3. Four columns: outcome (`decision_badge`, so the outcome string stays in markdown for P5-T11), tier, residual risk, confidence gauge.
4. Reason bullets under the grid. No heading. `report.summary`, when present, is one paragraph under the bullets. No Report heading.
5. Sections, fixed order, each with subheader, caption, body, and `see_raw`:
   - **Controls** — existing control table. Raw payload is the controls list. Evidence chips stay.
   - **Timeline** — existing graph, filters, and event table. Drop the inner subheaders `Agent collaboration graph` and `Agent timeline`. Raw payload is the trace.
   - **Contradictions** — existing table, or `st.info("No contradictions on this case.")`.
   - **Counterfactuals** — the bullet lines only. The extra heading `Evidence that would change this decision` goes away.
   - **Precedents considered** — existing table, or `st.info` with the current empty sentence.
   - **Actions** — existing contract cards, or `st.info("No contracts were issued for this case.")`.
   - **Trace and raw data** — `see_raw({"record", "report", "trace"})`.

No case selected: `st.info("Select a case from Cases, or run an assessment.")`.

The contradictions caption stays `A vendor claim and the system-of-record value it disagrees with.` so that P9 assertion can remain.

### Review

Top to bottom:

1. Title and caption. No bordered essay. No C05 block.
2. `st.selectbox("Case", ...)`. This is the first widget. The `Selected case · …` subheader goes away.
3. Status box from the existing per-render dry-run (`_eligibility_hint`). No Check eligibility button, and no second dry-run on a click. One dry-run per render. `see_raw(hint)` stays under the box.
4. Amber reasons live in `Why not eligible?`, not inside the warning string.
5. Decision selectbox.
6. Rationale (`st.text_area`, min 30). Character count caption stays.
7. Mitigations: `st.multiselect` with options `("assurance.bridge_letter_current",)`. When eligible and the widget key is unset, default that single option. When ineligible, disabled and empty.
8. Conditions: `st.multiselect` with `SOC 2 Type II report within 60 days` and `ISO 27001 certificate within 90 days`. Plus `st.text_input("Other condition")`. Disabled when ineligible. Not pre-filled.
9. Create precedent checkbox. Disabled and false when ineligible.
10. `Submit` (`type="primary"`) and `Dry-run`. Submit calls `submit_review` for real. Dry-run calls it with `dry_run=True` and the form body, then shows the payload in `see_raw` and does not say the review was recorded. Both reject a rationale under 30 characters.
11. Recent precedents: `get_case` reviews where `create_precedent` is true, columns review id, decision, reviewer. Omit the block when there are none.

`review_conditions(selected, other)` appends a non-blank Other condition after the selected options, without duplicates.
