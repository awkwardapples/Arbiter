# P9 plan: reviewer console explainability

**Phase:** build (tests first). **Branch:** `p9-ui-explain`. Marker stays `p5a`. Verify with `--pass 5a`.

## Goal

A judge who opens each page for about 30 seconds can say what it does and how to try it. Formatted sections replace raw JSON. Raw payloads stay in a collapsed **See raw** expander (`st.code(..., language="json")`), which is the same label the evidence chips already use.

## Scope

| Path | Action |
|---|---|
| `ui/components.py` | Pure formatters and the short copy constants. No new Streamlit calls except the existing renderers. |
| `ui/screens.py` | Wire those formatters into Case, Review, Memory, Audit, Queue, Evaluation. |
| `tests/unit/ui/test_polish.py` | Retarget the outcome and eligibility assertions that still expect a caption under the bullet. |
| `tests/unit/ui/test_pages_smoke.py` | **Approved exception.** `test_p5_t14_eval_not_published_on_404` only: missing summary vs present summary. |
| `tests/unit/ui/test_p9.py` | **Create.** `pytestmark = pytest.mark.p5a`. |

**Do not touch:** `app/`, schemas, `ui/client.py`, `ui/pages/` (they already call `ui.screens`), `tests/unit/ui/conftest.py`, any other test file, `pyproject.toml`, `docs/`. Tests mutate `FakeArbiterClient` the same way P8 does.

Both Python files stay under about 400 lines. Intro copy lives in `components.py` so `screens.py` does not grow past that.

## Shared formatters (`ui/components.py`)

```python
def humanised_bullet(code: str, sentence: str) -> str:
    """**CODE** — sentence. Unknown codes already come back as themselves."""

def see_raw(payload: object) -> None:
    """Collapsed expander labelled 'See raw'. Body is st.code(json.dumps(payload, indent=2, sort_keys=True), language='json')."""

def contradiction_rows(rows: list[dict]) -> list[dict[str, str]]:
    """Columns: Claim, System of record."""

def counterfactual_line(item: dict) -> str: ...
def precedent_rows(considered: list[dict], *, candidates: list[dict], as_of: str) -> list[dict[str, str]]: ...
def contract_card(contract: dict) -> dict[str, str]: ...
def ledger_line(entry: dict) -> str: ...
def signature_short(signature: str) -> str: ...
```

`see_raw` is the only new Streamlit helper. Everything else is pure and unit-tested without AppTest.

### Bullet order

Outcome reasons and eligibility reasons become one markdown bullet:

`**CONTRADICTION** — Contradiction on a system-of-record claim`

The separate `st.caption(code)` under those bullets goes away. The code is the bold prefix. An unknown code renders as `**NOT_A_REAL_CODE** — NOT_A_REAL_CODE`.

Replay check lines stay exactly as P8 locked them (`✓ policy hash matches`). They are check results, and `test_p8_replay_check_lines` asserts the current strings.

### See raw

Label is **See raw** (collapsed). The body is the parsed object for that section, pretty-printed. That is the API object the page already holds. It is not a second HTTP fetch and not a hand-written example.

Sections that get one: Contradictions, Actions (one expander for the contract list), Precedents, Counterfactuals, Replay, Verify, Eligibility. The case-page bottom dump becomes the same widget over `{"record", "report"}`. Submit-review success stops using `st.success(json.dumps(result))`.

`st.json` leaves `ui/screens.py`.

## A. Formatting

### 1. Contradictions — `page_case`

`st.dataframe` with two columns, `hide_index=True`.

| Claim | System of record |
|---|---|
| `{key}: {claim_value}` | `{sor_value}` |

`None` renders as `null` via the existing `_display_value`. The key is in the claim cell so two rows that share a bare value (often `false`) stay distinct. `sor_provenance` stays in **See raw** only.

Empty list: the caption, then `No contradictions on this case.`, then **See raw** of `[]`.

### 2. Actions — `page_case`

Each contract is `st.container(border=True)`:

| Line | Source |
|---|---|
| Contract id | `contract_id` |
| Intent | `intent` |
| Outcome | `parameters["outcome"]`, or `—` when that key is absent |
| State | `state` |
| Signature | `signature_short` + ` · ` + `signed_by` |
| Tool plan | one line per step: `capability` plus scalar `args` as `key=value` |

`signature_short`: signatures longer than 16 characters show the first 8, `…`, and the last 4. Shorter ones show in full.

Nested arg values are not printed on the card. They remain inside **See raw** of the full `contracts` list. Empty list: `No contracts were issued for this case.`

### 3. Precedents — `page_case`

Empty `precedents_considered`: `No precedents were considered for this case.`

Populated: a table with these columns only.

| precedent_id | confidence | age | applied |
|---|---|---|---|
| `precedent_id` | `hmem_confidence` (two decimals) | days between `record.as_of` and the matching candidate's `created_as_of` | `true` or `false` |

`PrecedentRef` has `hmem_confidence` and no age. Age comes from `record.policy_inputs.precedents` joined on `precedent_id` (`created_as_of`). A missing date or a bad date renders `—`. `failed_criteria` stays in **See raw**.

### 4. Counterfactuals — `page_case`

Remove the disabled checkboxes. They are the grey boxes.

```
st.subheader("What would change this")
st.caption(...)
st.markdown("**Evidence that would change this decision**")
st.markdown("- **C01** — Q01 and Q02 affirmative, naming the mechanism; or assurance report noting the MFA control without exception. Questions: Q01, Q02")
```

One bullet per counterfactual. Evidence strings join with `"; "`. No question ids renders `Questions: none`. The list is markdown only: no `st.container`, no checkbox, no code block around it.

### 5. Case id

| Page | Where |
|---|---|
| Case | `st.subheader(case_id)` directly under the outcome badge, before the reason bullets |
| Review | `st.subheader(f"Selected case · {case_id}")` once a real case is selected |
| Memory | same heading above the precedents-considered table |
| Audit | inside the verify card: `Active case · {id}` from `nav_case_id` or `last_case_id`. Each replay result opens with that case id in a bordered card. Clicking **Replay** stores that id in `nav_case_id`. |

Queue rows already show `CASE-0007`. The queue header does not gain a single case id.

### 6. Section captions — `page_case`

Expander **How to read this** at the top of a loaded case, `expanded=True`, so it is on screen without a click and can still be closed.

> The badge is the policy engine's outcome. Each bullet under it is a reason code, then what that code means. **Why** is the control and the fact behind it. **Contradictions** compare a vendor claim with a system of record. **What would change this** is evidence that is still missing. **Precedents** are exceptions the policy considered. **Actions** are signed contracts. **Agent timeline** is the trace of this run.

One caption under each section heading:

| Section | Caption |
|---|---|
| Contradictions | A vendor claim and the system-of-record value it disagrees with. |
| What would change this | Evidence that would flip a control if it were verified. |
| Precedents | Governed exceptions considered before this decision. |
| Actions | Signed contracts for the next step. This page does not run them. |
| Agent timeline | What each agent did on this run, in order. |

## B. Explainability

### 7. Review intro

A bordered container at the top, rendered before the case list is read, so it is visible with an empty queue and with a case selected.

**What this page does.** Record a human decision on the machine outcome. Tick **Create precedent** when that decision should be stored in H-MEM for a later case.

**A C05 precedent.** C05 is current independent assurance. Creating one needs all four: the only failing required control is C05, `assurance.bridge_letter_current` is TRUE, the decision is APPROVE or APPROVE_WITH_CONDITIONS, and the reviewer role is at least `tprm_lead`. This form sends `tprm_lead`.

**Try this.** On New assessment, run **VND-0011** (Marrowgate Analytics). It escalates with C05 failing and a current bridge letter. Select that case here, choose APPROVE_WITH_CONDITIONS, leave mitigations as `assurance.bridge_letter_current`, tick **Create precedent**, and submit. Then run **VND-0012** (Tessellate HR Cloud) and open the case. The policy can apply that precedent.

Copy lives in `REVIEW_INTRO` in `components.py`. The page renders it with `st.markdown`.

### 8. Review eligibility on select

`pending` means `list_cases()` returned at least one case. There is no separate pending status on `QueueItem`.

| State | Widget |
|---|---|
| No cases | `st.info("No cases awaiting review — run VND-0011 or VND-0012 first.")` The form stays hidden. |
| Case selected, dry-run `eligible` is false | `st.warning` whose body is `This case cannot create a precedent.` plus one `humanised_bullet` per reason, plus `You can still record this review. No precedent will be created.` |
| Case selected, dry-run `eligible` is true | `st.success` whose body is `This case can create a C05 precedent.` plus the four held lines below. |

Held lines (shown only when `eligible` is true; the dry-run does not return them, and an empty `reasons` list means all four passed):

- `**C05** — The only failing required control is C05, which allows a precedent`
- `**assurance.bridge_letter_current** — That mitigation fact is TRUE`
- `**APPROVE** — The decision is APPROVE or APPROVE_WITH_CONDITIONS`
- `**tprm_lead** — The reviewer role is high enough`

The dry-run runs on every render of a selected case, using the decision currently in the form. Rationale shorter than 30 characters is sent as 30 `x`s, same as today's **Check eligibility** button, so the hint does not fail validation while the box is empty. The button stays, so the existing click tests still have a target. One render draws the box once.

**See raw** holds the dry-run object `{eligible, reasons}`.

When `eligible` is true and `review_mitigations_{case_id}` is unset, set it to `assurance.bridge_letter_current` before the mitigations `text_input`. A value the reviewer already typed is left as it is. Switching cases uses a per-case key, so the default applies to the newly selected case.

### 9. Memory

`GET /memory/precedents` returns `precedent_id`, `hmem_id`, `confidence`, `control_id`, and `ledger` (a list of objects with `action`, `actor`, `memory_id`, `timestamp`, and often `previous_state` / `new_state` dicts). `st.dataframe` on that list is what the browser shows as `[object Object]`.

Render scalar columns only: precedent_id, hmem_id, confidence, control_id. Under the table, one markdown line per ledger entry:

`create · MemoryKeeper · mem-1 · 2026-10-22 08:00 UTC`

`timestamp` is epoch milliseconds. A missing or non-integer timestamp renders as `—`. State snapshots and `details` objects are not interpolated into the line. **See raw** holds the full precedents payload, ledger included.

Intro, same bordered pattern, above the table:

**What this page does.** Precedents stored in H-MEM, and the trust-ledger lines for each one. Pick a case to see which of those precedents the policy considered.

**Try this.** Create one from **VND-0011** on the Review page, then come back. The ledger should show a `create` line. Open **VND-0012** on the Case page to see whether that precedent was applied.

Auto-select: sort `list_cases()` by `created` descending, `get_case` until `precedents_considered` is non-empty, and use that id as the selectbox index on first load. If none have precedents, the index stays the first case in that recency order. The selected-case heading shows that id. The considered table uses the same `precedent_rows` helper as the Case page, with the same empty sentence and **See raw**.

### 10. Queue and Audit captions

Under the Queue header: `Assessed cases. Filter, then open one to see why it was decided.`

Under the Audit header: `Replay a case to confirm the same decision. Verify checks the hash chain for every case.`

Verify success and error strings stay as P8 specified. **See raw** is added under the verify result and under the replay result.

### 11. Evaluation

Resolve `eval/results/20261022T080517661769Z/summary.md` from `Path(__file__).resolve().parents[1]` so it does not depend on the working directory. The file is in this repo.

Header caption on every visit, as literal text: `` How these numbers were produced: `docs/EVALUATION.md`. `` A relative link does not navigate inside Streamlit, so the path is shown in backticks.

When the summary file exists, `st.markdown` its text. When it does not, keep today's API path: `client.eval_latest()`, and on 404 `st.info("Evaluation results are not published yet.")`.
