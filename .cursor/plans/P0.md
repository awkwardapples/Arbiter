## Build sequence (after approval)

1. Set `.cursor/ACTIVE_PASS` → `0 build`.
2. Commit failing tests: `test(p0): acceptance tests`.
3. Implement in layers: packaging → schemas → config/errors/canon → tracing → api/cli → scripts → stubs → gates → CI → PRIOR_WORK sha.
4. `python scripts/tasks.py verify-pass --pass 0` until green.
5. `docs/passes/P0_REPORT.md`, `docs/cursor-usage/P0.md`; push `p0-bootstrap`; delete `.cursor/ACTIVE_PASS`.

## Risks and questions

1. **Dependency pins:** Resolve exact versions with a fresh `pip install` during build (date: 2026-10-22). Any conflict between `streamlit` and FastAPI pins?
2. **`mask_secrets` vs `scan_secrets`:** Share one pattern module (e.g. `scripts/scan_secrets.py` exposing `SECRET_PATTERNS` imported by config/tracing) to avoid drift—OK to import from `scripts/` in `app/` or prefer a tiny `app/secrets_patterns.py`? *(Recommendation: shared module under `scripts/` imported by both; tests cover both paths.)*
3. **`RunResponse` shape:** §7 JSON is the contract; nested `output` fields may need flexible typing (`dict` vs strict sub-models) for P0-T3—prefer strict models matching the example with optional fields where the example omits them?
4. **Health payload:** P0-T6 only requires a `mode` block; confirm no requirement for provider/Zetaris status until P4-B (plan: minimal `{status, mode, versions?}`).
5. **Gate stubs p1a–p7:** Confirm `verify-pass` for pass 0 does not run other gates (only `p0.py`)—per tasks.py spec, each pass runs its own gate only.
6. **Hook smoke:** Definition of done asks noting hook fire once in report—human or agent triggers a build-phase save to observe `verify_loop.py`?
