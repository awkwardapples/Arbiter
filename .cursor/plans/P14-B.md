## Open decisions (need your answer before I code)

1. **Playwright dependency.** It isn't in `requirements.txt` or installed, and AGENTS.md says to add only what the spec allows. The spec names Playwright but `requirements.txt` isn't in my ownership. *Recommend:* `capture_ui.py` imports it lazily and prints install instructions (`pip install playwright && playwright install chromium`), with no pin added to `requirements.txt`.
2. **Questionnaire questions (16) and help text.** The UI must talk only to the API. The question texts live in `app/labels.py` (`question_text`) and the policy YAML, but no endpoint exposes them. Options:
   - (a) Add a small additive `GET /questions` route. This touches `app/`, which you said not to change beyond actions/workload.
   - (b) Embed a static list in `ui/intake.py`. This risks drifting from the policy.
   - (c) Derive them from the sample vendor's answers via an existing preset.
   *Recommend (a)* if you will allow it. Otherwise (b), with a test that fails if the ids differ from the policy's `question_ids`.
3. **USL model for the ERD.** `data/usl/vendor_risk.model.json` sits outside the API. Options: (a) the UI reads the file directly (a bounded exception to API-only), (b) an additive `GET /usl` route. *Recommend (a)* in read-only form (it is a committed, scrubbed artefact), and the same for `docs/passes/P1-B_parity.json`. Per-table row counts and DQ status come from `/health` only if it already exposes them. It currently returns just `{backend, ok}`, so otherwise I'd show the committed parity numbers labelled "as of the P13 run".
4. **Questionnaire controls.** You asked for dropdowns and yes/no. The spec says text areas for the 16 questions. *Recommend:* a yes/no/not-answered selectbox plus an optional "how" text area, composed into `answer_text` (e.g. "Yes. SAML SSO with TOTP."). The policy extraction needs a mechanism named in the answer, so the free-text part matters.
5. **Page count.** Your task says six pages, and the spec's capture list has seven shots (brief, next action, questionnaire, cases, sources, precedents, audit). I'll produce seven files unless you want six.
6. **Client additions.** `ui/client.py` gets `dossier()`. The `/contracts/{id}/approve` call already exists. Outbox file names for executed actions only appear if the contract's API payload carries them. I'll check against the recorded fixture and, if missing, show the contract state without a file name rather than invent one.
