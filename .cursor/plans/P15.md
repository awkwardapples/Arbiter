## 1. Steps and files

### Step A: `receipt_meta` (`app/llm/providers/meterless.py`, provider meta only)
- Keep `receipt_id`, `requested_model`, `provider_model`, `routed_model`, `decision_id`, `mode`; add flattened `app_policy.*` (incl. `mode_coerced`, `bound_mode`, `requested_mode`, `routed_mode`), `winning_route.model` (plus existing route keys), `cost.actual_usd` / `cost.naive_usd` / `cost.baseline.model`, `savings.*` scalars. Drop everything else (phases, egress, lineage, cache, prompts).
- Stays `dict[str, str]` so `TraceEvent.provider_meta` is unchanged.

### Step B: `python run.py llm proof` (`app/cli/llm.py`)
- Calls `generate()` once on `fast` and once on `deep` (tiny JSON task, `purpose="proof"`), with a tracer in a temp dir. Reads the `model_call` trace line each call writes (real execution, no second HTTP path) for `model`, `latency_ms`, `tokens_in/out`, `provider_meta`.
- Resolves the provider first. If it is not `meterless` (Nightshift unreachable or unauthorised): print `Nightshift not reachable: <detail>`, exit 1. If a call fails: print the HTTP status and scrubbed body from the `ProviderError`, exit 1, write nothing.
- Writes `docs/evidence/nightshift_proof.json` (overwrite, idempotent): `{timestamp, base_url (host only), fast:{requested_model, response_model, routed_model, provider_model, winning_route_model, mode_coerced, receipt_id, latency_ms, tokens_in, tokens_out, receipt:{…scrubbed subset}}, deep:{…}, deviations:[…]}`.
- `deviations` is computed, not canned: when `fast.response_model == deep.response_model`, or `fast` is not a Lightning id, it adds the "both lanes served by <model>" entry. The human-verified facts (UI binds fast to Lightning; direct NVIDIA curl for Lightning works; Super 3 120B returns 404 "Function not found for account" so Super VL is used; runtime routing bug is outside Arbiter) come from a committed, human-authored `docs/evidence/nightshift_deviations.md`, which the command links and quotes. This keeps generated JSON honest: code never asserts a fact it did not observe.
- Prints a table, base URL with the token hidden.
- Also writes `docs/evidence/nightshift_proof.schema.json` (for T7).

### Step C: labels and splits (`data/generator/generate.py`, `data/evals/*`)
- `_labels`: `expected_failing_controls` / `expected_unknown_controls` from running the policy engine's control evaluation over that vendor's `truth_facts` (same oracle as P3-T16). `expected_contradiction_keys` from truth `contradictions` (covers S06 `residency.regions` and S07).
- `_splits`: stratify so each scenario key with n ≥ 2 has ≥ 1 vendor in test; check S06, S07, S09, S11, S12 are in test. Record new split hashes.
- Regenerate with the existing seed and as-of. Only `labels.jsonl` and `splits.json` should change; I diff the rest of `data/sample/` and stop if anything else moves.
- Run the label oracle, then `python run.py calibrate` on the new calibration split (zero unsafe approvals). **Calibration writes `policy/calibration/**` (lane 14a).** See Q3.

### Step D: live harness (`eval/harness.py`, `eval/baseline.py` if needed)
- `run(..., live=True)`: `arbiter` uses `RunOptions(sample_mode=False, llm=None)` (Zetaris USL + Nightshift); `baseline` uses the same live backend and one `deep` Nemotron call; `arbiter_offline` keeps today's DuckDB + offline path. Settings are switched per system, not globally.
- `summary.json`: per-system `mode`, `model_ids` (from that system's traces only), `routed_models` (from `provider_meta.routed_model`), p50/p95 latency, model calls per case, fallback rate.
- `eval/report.py`: render the three-way table plus a per-lane routed-model line and the deviation note.
- A case subset option (`--cases N`, first N of the test split, sorted) for the reduced-n run.
- Entry point: see Q2 (`app/cli/eval.py` is not in my file list).

### Step E: live examples (`app/cli/examples.py`, `output_examples/**`, `logs/examples/live/`)
