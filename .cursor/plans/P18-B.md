# P18-B plan: web console foundation and the live run view (lane `18b`)

Tool: Claude Code (Opus 5.5). Spec: `docs/spec/release3/P18B_RUN_VIEW.md`, design `P18_00_DESIGN.md` (binding).

## 1. Goal

Build a new React console in `web/` that FastAPI serves at `/console/` once P18-A lands. Part 1 lays the
foundation that 18c and 18d build on: Vite + React 19 + TS strict, Tailwind 4 with the design tokens,
self-hosted fonts, the app shell with rail, mode chip and router (placeholders for every page 18c/18d own),
a typed API client and SSE hook, the shadcn-based component kit, and the Python toolchain hooks (build,
check, hardcode scan of `web/src`, dist freshness test, smoke script, gate). Part 2 builds the hero: the
Assess page and the run view, where one pure reducer turns trace events into the "bench" graph (vendor's
word left, records right, agents centre, reasoning band on top, ruling band below), whether events arrive
live over SSE, paced from a sample run, or replayed from a committed live trace. The view is exported as
`<RunCanvas>` so the Case page (18c) can replay any case's trace. No decision logic changes; the frontend
only renders what the trace says, and labels recordings and fallbacks honestly.

## 3. Interfaces and components

### API layer (`web/src/api`)

```ts
class ApiError extends Error { status: number; code: string; detail?: unknown }   // from ErrorResponse
api.get<T>(path, init?): Promise<T>;  api.post<T>(path, body): Promise<T>
// base = import.meta.env.VITE_API_BASE ?? "" (same origin)
useRunEvents(runId: string | null): { events: TraceEvent[]; done: DoneEvent | null; error: string | null; connected: boolean }
// EventSource on /runs/{id}/events; native Last-Event-ID reconnect; each `trace` data zod-parsed
// (passthrough for unknown fields); closes on `done` / `error`.
// queries.ts: useHealth, useVendors, useRecordings, useRecording(runId), useRegistry, useAgents, useCase(caseId)
```

`schema.d.ts` is generated with `openapi-typescript` from a running API (P18-A routes appear once merged;
I'll regenerate at part 2). `trace.d.ts` from `docs/trace_schema.json` via `json-schema-to-typescript`.
A Vitest test asserts every field the reducer reads is a key of the generated `TraceEvent` (design §11).

### Reducer state (`web/src/run/types.ts`)

```ts
type NodeKind = "agent" | "source" | "vendor" | "gate" | "engine" | "model" | "ruling" | "clash";
type RingState = "idle" | "active" | "done" | "fallback" | "failed";
interface BenchNode { id: string; kind: NodeKind; label: string; role: string; ring: RingState;
  count: number; countNoun: string; fellBack: boolean; firstIndex: number; eventIdx: number[] }
interface BenchEdge { id: string; from: string; to: string; type: "forward"|"sendback"|"replan"|"thread";
  tone: "record"|"claim"|"reason"|"clash"|"ink"; count: number; lastLabel: string;
  lastIndex: number; travelSeq: number; loopTotal?: number }
interface ClashItem { key?: string; control?: string; vendorValue?: string; recordValue?: string;
  system?: string; recordKey?: string; text: string; fromEvent: number }
interface InFlight { agent: string; purpose: string|null; route: string|null; startedAt: string; index: number }
interface Counters { critiques; sent_back; retries_fallbacks; shared_context; model_calls; zetaris; mirror: number }
interface Stage { name: StageName; visits: number; escalated: boolean }
interface RunState {
  runId: string|null; caseId: string|null; mode: {data:string; llm:string}|null; startedAt: string|null;
  nodes: Record<string, BenchNode>; edges: Record<string, BenchEdge>; activeNode: string|null;
  clash: ClashItem[]; stages: Stage[]; currentStage: StageName|null; safeEscalate: boolean;
  inFlight: InFlight[]; counters: Counters; fallbacks: number; coerced: boolean;
  outcome: { outcome: string; seconds: number|null } | null; index: number; events: TraceEvent[] }
reduce(state: RunState, event: TraceEvent, registry: Registry): RunState   // pure, never throws
initialState(): RunState
replay(events, registry, upTo?): RunState   // scrubber
type Registry = Record<string /*query id*/, { systems: string[]; description: string; sql?: string }>
```

Rules follow design §7.1/7.2 and pass §5 counters exactly; system → node mapping is derived from the
registry (`trust_portal` → `vendor.*` by query, the rest → `rec.<system>`), never a frontend list. Mode
chip text is computed by `modeChipText(state | health | recordingMeta)` per design §5.

### describe / pacer

```ts
describe(event: TraceEvent, registry: Registry): { text: string; detail?: string; tone: "plain"|"record"|"claim"|"reason"|"clash" }
type PaceMode = "live" | "paced" | "recorded";
createPacer({ events, mode, speed: 1|4|16, onApply(index), clock = realClock }):
  { start(); pause(); resume(); step(); seek(index); skipToEnd(); setSpeed(s); push(event) /* live */ }
dwellFor(event): number              // §6 dwell table

```
