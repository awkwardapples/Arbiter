# P3 agent loop plan

## Goal

Turn the P3 stubs into a real, bounded, multi-agent loop behind `POST /run` and `python run.py assess`. An explicit state machine drives five agents (Planner, Evidence, Evaluator, Challenger, Reporter) over the merged data layer, generator, guard, policy engine and contracts. The loop is "screen, then verify": iteration 1 reads what the vendor claims, the Evaluator finds controls whose only support is an unverified claim that a system of record can check, and it sends the Planner back for those queries. The policy engine decides twice (DECIDE₁ without precedents, DECIDE₂ with memory candidates; `NullMemory` until P4-A). The Challenger can only escalate or ask for one re-plan, the Reporter writes a cited report that is validated against the decision record, and the executor runs the signed contract or leaves it pending approval. Every model-backed step has a deterministic fallback, so all six input examples reach their expected outcomes offline on DuckDB, with honest traces that show the loops.

## State table (`app/orchestrator.py`)

| From | Condition | To | Trace (`Orchestrator/transition`) |
|---|---|---|---|
| INTAKE | input valid, profile loaded | PLAN | `INTAKE→PLAN` |
| PLAN | always | GATHER | `PLAN→GATHER (n queries)` |
| GATHER | always | EVALUATE | `GATHER→EVALUATE` |
| EVALUATE | `needs_revision` and `eval_loops < 2` | PLAN | `EVALUATE→PLAN (gaps: C06,C09)`, status `needs_revision` |
| EVALUATE | sufficient, or loops exhausted | DECIDE_1 | `EVALUATE→DECIDE_1`; exhausted → `partial_success` |
| DECIDE_1 | always | MEMORY_CHECK | |
| MEMORY_CHECK | always | DECIDE_2 | candidates for DECIDE₁'s failing exception-eligible controls; confidence recomputed |
| DECIDE_2 | always | CHALLENGE | traced `redecide` |
| CHALLENGE | `re_plan` and `challenge_loops < 1` | PLAN | `request_replan` |
| CHALLENGE | `escalate` | REPORT | `force_escalate(DECIDE₂, reason)`, status `escalated` |
| CHALLENGE | `accept` | REPORT | |
| REPORT | always | CONTRACT | |
| CONTRACT | always | EXECUTE | |
| EXECUTE | always | DONE | `complete_run` with outcome and duration |
| any | unhandled exception or `BudgetExceeded` (budget checked before every state) | SAFE_ESCALATE | status `error` |
| SAFE_ESCALATE | `decide(facts so far)` + `force_escalate("SYSTEM_<ErrorType>")`; if `decide` fails, `DecisionRecord.safe_escalation(...)` | REPORT (template forced) | status `escalated` |

`transition(state, st) -> State` is a pure table lookup plus guard predicates; a test drives it with fake agents. After the challenger loop is spent, a second `re_plan` becomes `escalate`. `MAX_EVAL_LOOPS=2`, `MAX_CHALLENGE_LOOPS=1`, `RUN_BUDGET_SECONDS` from settings, `as_of = settings.ARBITER_AS_OF`.

## Agent I/O

| Agent | Reads from `CaseState` | Writes | LLM (route, schema) | Deterministic fallback |
|---|---|---|---|---|
| PlannerAgent | profile, tier hint, executed ids, latest gaps, challenge request, budget | `plans[]` (query id, params, reason) | deep, `PlanOut` | §5 screen set in iteration 1; afterwards the Evaluator's/Challenger's suggested ids |
| EvidenceAgent | latest plan | `executed_queries`, `segments` (with `GuardResult`), `claims`, `guard_flags`, `evidence_index` | fast, `ClaimListOut` (one batched call over unblocked, redacted answers in `<vendor_text>`) | `app/extract/deterministic.py` |
| EvaluatorAgent | claims, executed queries, policy | grounded flags, `facts`, `contradictions`, `dq_flags`, `evaluations[]` (`EvaluationReport`) | fast, `CritiqueOut` (TRUE→UNKNOWN downgrades only) | code only (critic skipped) |
| PolicyEngine (code) | facts, contradictions, guard flags, precedents, confidence | `decision` | none | n/a |
| ChallengerAgent | decision, facts, precedents, profile, loops left | `challenge` (`accept`/`re_plan`/`escalate`) | deep, `ChallengeOut` only when candidate is APPROVE or APPROVE_WITH_CONDITIONS | triggers (a) T1 C01 answer-only, (b) disputed precedent, (c) T1 near-match |
| ReporterAgent | decision, facts, counterfactuals, questions | `report` | deep, `ReportOut` | `template:v1` built from the record |
| ActionExecutor (code) | decision, report | `contracts[]`, outbox file | none | n/a |

Params are always built in code from the case (`vendor_id`, aliases, `since = as_of − 730 d`, product lists); any `params` the model returns are discarded.

## Interfaces

```python
# app/orchestrator.py
class State(StrEnum): INTAKE, PLAN, GATHER, EVALUATE, DECIDE_1, MEMORY_CHECK, DECIDE_2, CHALLENGE,
                      REPORT, CONTRACT, EXECUTE, SAFE_ESCALATE, DONE
MAX_EVAL_LOOPS = 2; MAX_CHALLENGE_LOOPS = 1
class RunOptions(BaseModel): sample_mode: bool | None = None; llm: Literal["auto","meterless","nvidia","offline"] | None = None
class Deps(BaseModel):  # arbitrary_types_allowed
    backend_factory: Callable[[Settings, Tracer, VendorSubmission | None], DataBackend]
    generator: Callable[..., GenerationResult]   # same signature as app.llm.generator.generate
    memory: MemoryPort; sink: Store; clock: Callable[[], datetime]
    tracer_factory: Callable[[str, dict[str, str]], Tracer]; var_dir: Path = Path("var")
    agents: dict[State, Agent] | None = None     # test seam for P3-T1
def transition(state: State, st: CaseState) -> State
def run(case_input: CaseInput, *, options: RunOptions, deps: Deps | None = None) -> RunResponse

# app/agents/base.py
class Agent(Protocol): name: str; role: str; def __call__(self, state: CaseState, ctx: AgentContext) -> CaseState
@dataclass class AgentContext: tracer, backend, generator, policy, calibration, memory, settings, clock, degraded: bool
def llm_or_fallback(ctx, fn_llm: Callable[[], T], fn_det: Callable[[], T], *, purpose: str, agent: str) -> tuple[T, str]
    # catches OfflineProvider, ParseFailure, UpstreamTimeout, UpstreamError, Unauthorized;
    # traces status=fallback provider=offline; upstream errors set ctx.degraded=True for the run

# app/agents/memory_port.py
class MemoryPort(Protocol):
    def find_precedents(self, profile: TierProfile, failing_controls: list[str]) -> list[PrecedentCandidate]
    def prior_assessments(self, vendor_ref: str) -> list[dict[str, Any]]
    def record_assessment(self, record: DecisionRecord) -> None
class NullMemory: ...  # empty lists, no-op

# app/extract/deterministic.py
def extract(question_id: str, answer_text: str, *, answer_ref: str) -> list[ExtractedClaim]  # pure
def sentences(text: str) -> list[str]
# app/grounding.py
def normalise(text: str) -> str; def is_grounded(quote: str, source: str) -> bool
# app/facts.py
def derive(state: CaseState, policy: Policy) -> tuple[list[Fact], list[Contradiction]]
# app/confidence.py
def compute(state: CaseState, calibration: Calibration, *, tier: Tier, precedent_alignment: float = 1.0) -> ConfidenceBreakdown
# app/actions/executor.py
class ExecutionResult(BaseModel): contract: ExecutionContract; status: Literal["executed","pending_approval","rejected"]; reason: str; artifact: str | None
def execute(contract: ExecutionContract, *, now: datetime, policy: Policy, outbox_dir: Path, tracer: Tracer | None = None) -> ExecutionResult
# app/actions/outbox.py
def write(contract: ExecutionContract, payload: dict, *, root: Path) -> Path   # system from capability
# app/store.py
class Store: save(bundle), get(case_id), list(order="risk"), put_contract(c), contracts_for(case_id),
             put_review(r), reviews_for(case_id), put_human_decision(record)
```

`case_id` is derived in code (`CASE-<digits of vendor_id>` for vendor cases, `CASE-<SUB hash>` for inline); no literal ids anywhere in `app/`. Fact ids `F-<control>-<n>`, evidence ids `E-<system>-<record_key>`.
