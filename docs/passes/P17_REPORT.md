## Deviations from the spec, with reasons

- **Offline count is 16/16**, not 15/15 as in the prompt: the committed summary (approved).
- **P17-T6 evidence scope.** Lightning appears in `logs/examples/live/` only inside a 502 error string. So T6 accepts a receipt from `logs/examples/live/`, `eval/results_live/` or `docs/evidence/nightshift_proof.json` for each model id. Super VL must still have one in `logs/examples/live/`.
- **Federated KEV join evidence** is the live eval trace `run-257c86984507` (Quillfeather, 15 KEV rows through Zetaris). No `logs/examples/live/` run executed `Q_COMPONENT_KEV`.
- **Demo narration.** The spec's "vulnerability catalogue is CISA's live feed" is false: Zetaris federates the committed 84-row snapshot (`docs/ZETARIS_USL.md` §7). The script says "CISA's public KEV catalogue". The spec's monitoring shot is dropped because P16 did not ship.
- **Reporter wording.** `app/agents/reporter.py` can call the deep lane. The live runs used `template:v1`, so the docs say that, not "deterministic by design".
- **AI usage.** The record shows P14-A was Cursor (Grok 4.7), so the README says P0–P14-A in Cursor, and P14-B, P15 and P17 in Claude Code. The prompt said "in VS Code", but P15's note records the Claude Code CLI, so the README says only "Claude Code". No separate `docs/CLAUDE_CODE_USAGE.md` was added: the README section plus the compiled table cover it.
- **Statistics test.** T3 matches the specific cited figures (48%, 2,643, 36%, 37.4 and so on), not every percentage, so that eval rates and estimates are not mistaken for industry statistics.
