## How this run was made

```bash
METERLESS_NO_THINK=1 python run.py eval --live --split test --systems arbiter,baseline,arbiter_offline \
  --cases 5 --consistency 4x2 --publish
```

- **Live systems:** `arbiter` and `baseline` ran on the Zetaris USL and Meterless Nightshift with `LLM_PROVIDER=meterless` and `METERLESS_NO_THINK=1`. They used the first 5 test cases by case id: VND-0001, VND-0003, VND-0004, VND-0006 and VND-0007. Each also ran 4 consistency repeats of the first 4 cases.
- **Offline system:** `arbiter_offline` ran the whole test split (n=16) on the DuckDB mirror and the offline generator.
- **Concurrency:** 1.
- **Results:** `eval/results_live/20261024T045916036274Z/`, with every trace under `traces/`.
- **Routing:** while this ran, a Nightshift app rule coerced both lanes to `auto` (`docs/evidence/nightshift_deviations.md`). The routed models above come from the trace receipts, not from the lane design.

## Labels and splits changed (B8)

The labels and splits changed in P15, before this run.

- `expected_failing_controls`, `expected_unknown_controls` and `expected_contradiction_keys` are now produced by running the policy engine on each vendor's truth facts, the same oracle as P3-T16. Previously the failing controls were empty for all 32 vendors.
- The split is stratified per scenario code, so S06, S07, S09, S11 and S12 all have a test vendor. VND-0007 (S06+S09, a `residency.regions` contradiction) moved into the test split.

The earlier published evaluation was offline-only and had incomplete labels, so changing the splits after it is acceptable. The offline test split grew from 15 to 16 cases. Re-calibrating on the new calibration split left the gates unchanged: 0.95 for every tier, 16/16 correct, 0 unsafe approvals. Nothing under `policy/calibration/` was changed.

## Discussion

**The baseline was not measured.**
- All 9 baseline calls returned HTTP 502 from Nightshift: 7 `nvidia/nemotron-3.5-lightning-30b-a3b_empty_response` and 2 `provider_deadline`.
- The baseline sends one large deep-lane prompt (the policy plus all the evidence). The app rule coerced it to `auto`, which routed it to Lightning, and Lightning returned an empty response even with `/no_think`.
- So the baseline's 0/5 and 5/5 INVALID measure Nightshift's routing, not single-LLM decision quality. **Do not read this run as Arbiter beating the baseline.** Its 1.000 consistency only means it was invalid every time.
- A real comparison needs the routing fix that Meterless has announced, or a run with lane routing honoured. Until then, the baseline comparison is open.

**Arbiter live:**
- 5/5 correct, 0 unsafe approvals, 4/4 consistent repeats with stable fact hashes.
- Contradiction recall 1/1 (VND-0007 `residency.regions`) and failing-control recall 2/2.
- **Latency:** p50 141.8 s, p95 233.3 s per case, against p50 0.4 s offline. The live cost is almost entirely model calls, which took 13–41 s each in live example 1.
- **Model calls:** 5.0 per case (25 over the 5 primary runs). 20 succeeded with Nightshift receipts:
  - plan ×8 and challenge ×3 on the deep lane;
  - extract ×5 and critique ×4 on the fast lane.
- **Models:** 19 of the 20 successful calls were served by `nvidia/nemotron-3.5-super-vl-120b-a12b` and one deep call by `nvidia/nemotron-3.5-lightning-30b-a3b`. The fast lane never reached Lightning in this run.
- **Fallbacks:** 5 of 25 calls (0.20), plan ×4 and critique ×1, all HTTP 502. Each fell back to the deterministic step and the trace labels it `fallback`.

Because a model only extracts, critiques, challenges and plans, and the policy engine decides, a fallback changes the evidence path but not who decides. All five live outcomes matched their labels.

**Earlier live example (before `/no_think`).** Example 1 returned REQUEST_INFO instead of APPROVE: the model's extraction missed the vendor's MFA and encryption answers, which left C01 and C04 UNKNOWN. A worse extraction lowered the outcome; it never raised it. With `/no_think` the same example returned APPROVE (`logs/examples/live/trace-run-83de5da137c0.jsonl`). n is small, and this is one observation, not a rate.

**Small n.** Five live cases give a Wilson 95% interval of 0.57–1.00 on accuracy. These numbers show that the live path works end to end. They are not a precision estimate.
